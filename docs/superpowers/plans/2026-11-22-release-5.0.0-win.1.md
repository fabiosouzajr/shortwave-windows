# Release 5.0.0-win.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the first Windows-port release `5.0.0-win.1`: version bump, release docs, tag, GitHub Release with installer and zip.

**Architecture:** The version lives in `meson.build` and flows to the app, the exe resources (`build.rs`) and the bundle/installer names. Docs are Markdown in the repo; the release notes file doubles as the GitHub Release body. Artifacts are built locally and attached with `gh`.

**Tech Stack:** Meson, Rust build script (winresource), Inno Setup, PowerShell build scripts, GitHub CLI.

**Spec:** `docs/superpowers/specs/2026-11-22-release-5.0.0-win.1-design.md`

## Global Constraints

- Version string exactly `5.0.0-win.1`; tag exactly `v5.0.0-win.1`; binary VERSIONINFO `5.0.0.1`.
- Release title: `Shortwave for Windows 5.0.0-win.1`; latest, not pre-release.
- Artifacts: `dist\Shortwave-5.0.0-win.1-windows-x64-setup.exe`, `dist\Shortwave-5.0.0-win.1-windows-x64.zip`.
- Binaries built only from the committed tree (`git status --short` empty before building).
- The user's pending `src/main.rs` change is committed with the release (user decision).
- Never kill the user's running Shortwave; ask them to close it before bundling.
- Tests: MSYS2 UCRT64, `export CARGO_HOME=$PWD/_build/cargo-home`, `cargo test --locked`.

## Review Focus

1. A stale `dist\Shortwave-5.0.0-*` from Nov 20 gets attached by mistake → attach only files whose names carry `5.0.0-win.1` and whose timestamp is from this run (Task 4 check).
2. `build.rs` only reruns on `meson.build` changes, so a stale exe keeps `5.0.0` → Task 4 checks the installed exe's ProductVersion.
3. `numeric_version("5.0.0")` must still give `5.0.0.0` (Task 1 check).
4. README/CHANGELOG links must resolve to existing files (Task 2 check).
5. Release notes describe only what is in this build; unverified items are listed as known issues, not features (Task 2 review against WINDOWS-PORT-STATUS).
