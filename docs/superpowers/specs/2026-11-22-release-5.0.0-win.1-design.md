# First release: 5.0.0-win.1

## Intent
Publish the first release of the unofficial Windows port, with documentation
describing everything done since forking upstream Shortwave 5.0.0.

## Goals
- Version `5.0.0-win.1` everywhere the app shows or ships a version.
- Docs: changelog, release notes, refreshed README and status doc.
- Annotated tag `v5.0.0-win.1` and a GitHub Release with installer + zip.

## Non-goals
- No CI release job (approach B, deferred to a later release).
- No change to the Linux AppStream metainfo `<releases>` (upstream's file).
- No new features or fixes.

## Anti-goals
- Released binaries must be built from exactly the tagged commit (no
  uncommitted changes compiled in).
- Must not overwrite or kill the user's running `dist\Shortwave` instance
  without them closing it.

## Approaches (chosen: A)
- **A. Local build, `gh release create` (chosen).** CI already proves the
  build on a clean runner.
- B. Tag-triggered CI release job: repeatable, but more work now and slow to
  debug.
- C. Tag + docs only: nothing downloadable.

## Design
**Version**
- `meson.build` `version: '5.0.0-win.1'` → About dialog, exe
  ProductVersion/FileVersion strings, bundle/installer file names
  (`Shortwave-5.0.0-win.1-windows-x64{.zip,-setup.exe}`).
- `build.rs::numeric_version` reads a 4th number so the binary VERSIONINFO is
  `5.0.0.1` (unit-tested; `5.0.0` stays `5.0.0.0`).
- `packaging/windows/shortwave.iss` default `AppVersion` → `5.0.0-win.1`
  (only used when ISCC runs without `/DAppVersion`).

**Docs** (written for people downloading the app; developer detail stays in
`docs/`)
- `CHANGELOG.md` (new, Keep a Changelog style): one section `5.0.0-win.1 —
  2026-11-22` with Added / Changed / Fixed / Known issues, from the git
  history since `gnome-5.0.0`.
- `docs/releases/5.0.0-win.1.md` (new): release notes, used verbatim as the
  GitHub Release text: what it is, download choices (installer vs portable),
  highlights, known issues, system requirements (Windows 10/11 x64).
- `README.md`: Installation points to the Releases page first, building
  yourself second; feature list adds flags, heart, search filters, logos,
  codec/bitrate meter, language choice; link to CHANGELOG.
- `docs/WINDOWS-PORT-STATUS.md`: date, branch `main`, new features under
  "What works", new rows for features not yet verified in the running app.

**Release steps**
1. Commit version + docs on `main`, together with the user's pending
   `src/main.rs` change (drops a redundant `unsafe` around `glib::setenv`;
   user decision), push (CI runs on the commit).
2. User closes the running Shortwave (it runs from `dist\Shortwave`, which
   the bundle step rewrites).
3. `build.ps1`, `bundle.ps1`, `installer.ps1`; check both file names carry
   `5.0.0-win.1` and the exe's ProductVersion is `5.0.0-win.1`.
4. `git tag -a v5.0.0-win.1`, push the tag.
5. `gh release create v5.0.0-win.1 --title "Shortwave for Windows 5.0.0-win.1"
   --notes-file docs/releases/5.0.0-win.1.md` with both files; marked as
   latest, not pre-release (my call: it's the first real release).
